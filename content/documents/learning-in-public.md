# Learning in public

Writing forces an idea to survive outside my head. The useful part is not presenting a perfect answer. It is making the path clear enough that I can return to it, challenge it, and connect it to a later discovery.

Technical notes often begin with a concrete problem, like [finding database bottlenecks](/blog/finding-database-bottlenecks). Personal documents begin in a different place, but the same habit applies: observe carefully, name what changed, and leave a trail.

## A small practice

I try to capture the question, the evidence, the decision, and what I would test next. That structure keeps a note useful without pretending it is final.

[Photography as observation](/blog/photography-as-observation) follows the same practice without code.
